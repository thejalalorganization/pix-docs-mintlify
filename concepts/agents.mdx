Pix gives you a single workspace to run, switch between, and coordinate multiple coding AI runtimes — called agents. Instead of juggling separate tools, you work from one interface while Pix handles how each agent is connected, what controls are shown, and how context moves between them.

## What Is an Agent?

In Pix, an **agent** is a coding AI runtime that Pix connects to on your behalf. When you send a message, Pix attaches the selected agent, routes your input, and streams its response back into your session. Agents are **not** woken just to browse history — Pix loads past sessions instantly without touching the runtime, so you only consume tokens when you actually need the agent to act.

## Capability-Honest Design

Different agents support different features: some handle file attachments, some stream tool calls, some support multi-turn context, and some do not. Rather than showing you every possible control and silently failing when an agent can't fulfill it, Pix surfaces **only the controls a given agent genuinely supports**.

This means every button, toggle, and action you see has a clear contract — if it's visible, it works.

<Note>
  When you switch agents, the available controls may change. This reflects real differences in what each runtime supports, not missing features in Pix.
</Note>

## Switching Agents

You can hand work to a different agent at any point without losing your place. When you switch:

<Steps>
  <Step title="Select a new agent">
    Open the agent picker in the composer and choose the agent you want to continue with.
  </Step>
  <Step title="Context is preserved">
    Your conversation history and project context remain in the session. The new agent picks up from where the previous one left off.
  </Step>
  <Step title="Controls update">
    The toolbar updates to reflect what the newly selected agent supports. Any capabilities not available for that runtime are hidden automatically.
  </Step>
</Steps>

<Tip>
  Use agent switching for handoffs — for example, plan a feature with Pi, then pass execution to Claude Code without starting a new session.
</Tip>

## How Pix Attaches Runtimes

Pix connects to an agent's runtime **only when you send a message**. Browsing session history, searching past tool calls, or reviewing file changes never wakes an agent. This keeps history exploration fast and your token usage predictable — the runtime is engaged exactly when you need it and idle the rest of the time.
